# Original source sky mesh material

The `M_SimpleSkyDome` route now uses the original source SkySphere geometry and the original UE sky-view / sun-disk material intrinsics. It is a primary `UELegacyGBufferPass` consuming graph textures and buffers. Final `2.rdc` image agreement remains unproven.

## Rendering contract

`prepare_source_sky_material()` copies the source Scene document, verifies the expected source material and Unlit model, and enables its external material program. The historical `SkyDomePending` key remains stable for existing opaque-only source fixtures. `targetmap_graph(..., sky_material=True)` adds the third material partition and includes that original instance in the shared PrePass. Packed attachments and coverage flow Base0 → Base1 → Base2 → Decode/Lighting; the shared native depth includes the sky. Lighting preserves Unlit emissive, and its output feeds the existing histogram/automatic-exposure chain.

The material reads the current 160-byte native sky setup, R11G11B10 SkyView and transmittance LUTs, current `ExposureFrame.preExposure`, and `ExposurePrevious.status.z` modulo eight. The view intrinsic removes the LUT's pre-exposure before source noise; the disk is physical luminance; the common Unlit codec applies pre-exposure once to their sum. `SkyLuminanceFactor` is read separately from the component: it is not the `SkyAndAerialPerspectiveLuminanceFactor` already used by the LUT integrator.

Schema owns the model ID. The wrapper returns only the Unlit-relevant emissive and incoming model ID; other logical surface fields are zero and ignored by the Unlit codec. This avoids carrying unused lit fields through the sky expression. The targetmap composition uses RGBA16Float SceneColor and its original `ComputePixelFormatQuantizationError` value (2^-10 per RGB channel). `materialBindings.fieldFormats` now enforces this assumption through the actual logical `sceneRadiance` field's attachment, including renamed or relocated resources. It does not auto-derive constants for arbitrary formats. Six native rejection cases and a successful field relocation passed in `build/material-field-formats/run-2m3g4i6x` (launcher `run-ugmxss0y`).

## Source fidelity

`export_sky_material_source.py` retains 23 exact source excerpts with original file/span SHA256 values, byte offsets and source lines in `Atmosphere/UESkyMaterialSource.json`. They cover material intrinsics, UV mapping, fast trig, ray/sphere intersection, decoded transmittance, softened disk, quantization and interleaved gradient noise. The FastMath MIT notice and exact CPU pixel-format quantization function are retained beside them.

The original intrinsics are preserved in `UESkyMaterialOriginal.ush`. The executable perspective specialization removes only the two original orthographic blocks, with exact removed-range hashes and reconstruction tests. Reflection capture, primitive alpha holdout and orthographic material paths are not implemented by this main-view route. Native Mesh rendering already rejects an orthographic focal length. No UE source or source project is modified; no RDC geometry, constants, LUT, texture, depth, exposure or history enters rendering.

## Material controls and verification

The native UELegacy Release build passed, including packaging the original sky source/helper shaders (`build/sky-material-native-build.log`). The complete Python suite passed 405 tests (`build/sky-material-python-tests.log`); 11 cover the sky material's graph, source provenance and independent math. `git diff --check` passed.

The expanded serial batch `build/sky-material-controls/batch-zy14vl4t/result.json` passed all five native cases: temporal, exposure4, blocked, gradient and schema7. The shader SHA256 is identical across cases. Exposure-normalized sky RGB is exactly unchanged at four-times pre-exposure, and migrating Unlit from ID 0 to ID 7 leaves the complete lighting image identical. Frame 0 and 8 match exactly; frame 1 and camera motion change the image. The same graph rejects an orthographic camera.

The compact-planet gradient case uses a non-symmetric orthonormal basis and covers 49,601 sky pixels: 27,424 safely in the upper-sky mapping and 21,965 in ground mapping. Both identity and transposed-basis wrong models exceed the comparison budget for all 49,601 pixels. Maximum RGB difference from the independent ideal oracle is 0.0116684 under rtol=0.003, atol=0.006, covering float angular arithmetic, packed bilinear filtering and half storage. This case intentionally sets disk luminance to zero to isolate mapping from the discontinuous planet-shadow boundary. Disk center/soft edge/outside and fully blocked controls run separately; a ray exactly tangent to the virtual planet can disagree with FP64 on visibility and is not a bit-exact acceptance claim.

The constant-LUT noise comparison additionally uses a conservative FP32 arithmetic interval followed by positive half conversion toward zero. Fraction wrap crossings are handled explicitly. The fixture uses factor 1.1 to keep values off the half grid; half-amplitude noise is rejected for over 59,000 channels. An independent review's 32 arithmetic variants stayed inside the interval. The final oracle excludes the disk's angular uncertainty band and restricts its input domain away from exponent boundaries; the final temporal/motion rerun passed in launcher `run-nzv3jsuh`. These are fixed native authored inputs, not a numerical enclosure for the source planet or arbitrary filtered LUTs.

Source targetmap shared-depth/opaque/exposure integration passed at the authored 1421×1035 extent: `build/sky-material-gpu/batch-tp4a295z/result.json`. Baseline is `run-lknk2qlp` / launcher `run-99mbyejc`, sky is `run-ihue_hpu` / launcher `run-6_wxuwye`. Their source hash, Schema, native scene identity and extent agree; the generated Schema/Codec identity also matches (`shared-generation-check.json`). Baseline readbacks are comparison-only and never enter the graph.

The scene has 212,225 sky and 1,258,510 opaque pixels. All original opaque Packed GBuffer/decoded material/depth values remain identical; first-frame opaque lighting and shadows also match. Unlit sky preserves scene color, receives no direct BRDF term, and participates in shared native depth and exposure metering. Draw counts are 5/3/1/1 for Depth/Base0/Base1/Base2. Pre-exposure evolves from 1 to 1.31735599 to 1.31734371 over three frames. Raw arrays, actual depth/stencil planes and the inspected eight-tile Atlas are in `run-ihue_hpu`. This is source integration evidence, not a comparison to the final RDC image.

## Compiler-memory investigation

One early integration run compiled/drew the sky and then failed because the test indexed flat Packed storage as a logical image; the test now reshapes raw storage without channel reinterpretation. Subsequent Slang compiles ended with code 2170 and an access violation while Windows also reported insufficient page-file capacity. `build/sky-material-gpu/run-y_6blq8p/fault.dmp` and `build/sky-material-crash-analysis.log` place the fault in Slang; private compiler symbols are absent, so the exact failure path is not established.

Returning a fresh Unlit surface while retaining its dynamic Schema ID subsequently compiled and drew in about 32 seconds at roughly 6.6 GiB process private memory. Multiple test graphs in one process still accumulated substantial compiler memory (17.6 GiB peak in the earlier passing constant controls). Independent test cases therefore run serially in separate processes, with same-graph temporal/motion cases kept together. Final controls peaked at 6.50–6.64 GiB except temporal/motion at 9.83 GiB. The full-extent combined source run hit the scoped launcher's 1 GiB system-commit reserve (`run-ds4nt8oj`); it stopped only its own test process. The first split script also continued after Mogwai's non-terminating `exit()` request (`run-a15rn84y`), which an explicit branch now prevents. No other applications or page-file settings were changed. These measures do not establish that every prior intermittent compiler crash is fixed.
